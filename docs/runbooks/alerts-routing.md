# Alert 路由与值班策略

**版本**: 1.0  
**日期**: 2026-02-12

## 1. 严重等级

1. P0: 服务不可用、数据丢失风险、批量任务不可恢复失败。
2. P1: 转码成功率显著下降、清理失败持续堆积、吞吐明显塌陷。
3. P2: 队列增长、单点组件抖动、容量临近阈值。

## 2. 路由策略

1. P0: 立即电话 + IM 群 @OnCall，5 分钟内未确认自动升级到值班负责人。
2. P1: IM 群告警 + 工单，15 分钟内确认。
3. P2: 工作时段通知 + 日报汇总。

## 3. 去重与抑制

1. 同一告警实例 `group_by: [alertname, instance]`。
2. `repeat_interval: 30m`（P0 例外，10m）。
3. 维护窗口期间抑制非 P0 告警。

## 4. 升级链路

1. L1 值班工程师（5 分钟响应）。
2. L2 模块负责人（10 分钟内接入）。
3. L3 技术负责人（30 分钟内决策回滚/降级）。

## 5. 执行检查清单

1. 告警消息包含：实例、错误类别、最近变更版本。
2. 告警链接可直达 Dashboard 和 Runbook。
3. 每周抽检 3 条历史告警，验证路由准确性。
